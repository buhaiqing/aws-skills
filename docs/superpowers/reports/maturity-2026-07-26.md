## 1. 方法学

与 L4 closure review (l4-final.md) 不同, 本次重新审视**不预设目标**为 L4=100%,
而是按真实证据逐项审计:

1. **结构性审计** (Charter C1-C7) — 跑 shell 脚本扫描 37 个 skill 的章节 / frontmatter
2. **交叉引用审计** — 解析每个 SKILL.md 中的 `aws-X-ops` 引用, 验证目标目录存在
3. **测试覆盖审计** — 数 test_*.py 文件数 + 测试函数数 + 测试运行覆盖率
4. **集成强制力审计** — pre-commit hook 是否默认安装? GCL trace 是否自动清理?
5. **e2e 缺口审计** — 是否有脚本能"读完 SKILL.md → 实际跑 AWS CLI → 验证输出"?

### 3.2 真实缺口 (8%)

**Gap L2.1**: **pre-commit hook 默认未安装** — `scripts/hooks/pre-commit` 存在且功能完整,
但需要 `git config core.hooksPath scripts/hooks` (由 `install-hooks.sh` 完成) 才能生效。
新 clone 的仓库**默认无任何 lint gate**, 直到用户主动运行 install-hooks.sh。
**风险**: 开发者可能提交违反 Charter 的 skill 而不被拦截。
**修复方向**: 加 `make setup` / `npm postinstall` / GitHub Action `setup` job 在 CI 强制 install。
**修复成本**: ~30 行 YAML (GitHub Actions)。

**Gap L2.2**: **Composite skill 的 `delegate:` 自动化校验缺失** — `aws-aiops-copilot` 等
composite skill 声明 `delegate: aws-aiops-cruise`, 但**没有测试**确保 delegate 目标
真实存在 + 真的提供该 operation。人工 review 容易漏检。
**修复方向**: 扩展 `scripts/cross_runtime_lint.py` 或新增 `scripts/composite_lint.py`:
- 读 composite SKILL.md frontmatter 的 `delegate:` 块
- 对每个 (delegate_target, operation) 调用目标 skill 的 `metadata.provides` 验证
**修复成本**: ~80 行 + 6 测试。

### 3.3 L2 verdict = **92%**

> 实现完整, 但**强制生效机制** (pre-commit default-on, composite auto-lint) 缺位。

**Scripts 实现**: 7/7 ✅, 76 KB 代码 + 53 测试函数 / 70 测试实例 (含 parametrize).

### 5.2 真实缺口 (12%)

**Gap L4.1**: **Pre-commit hard gate 非默认开启** — 与 L2 Gap 同源, 影响所有 §15-§21
脚本的"实战触发率"。开发者 clone 后默认不 install hooks, 导致 §16/§17/§18 等的
防护不生效。
**修复方向**: 同 L2.1 修复。

**Gap L4.2**: **Skill 内容 e2e 测试缺失** — 当前 98 测试实例**全部针对 scripts/**
(`runtime_safety.py`, `golden_eval.py` 等), 但**没有任何测试**能:
- 读 SKILL.md → 解析 operations
- 实际跑 `aws <svc> <op> --output json` (mock 或 fixture)
- 验证输出符合 SKILL.md 描述的预期
也就是说, **scripts/ 的代码质量有保障, 但 skill 内容的"承诺正确性"无人验证**。
**修复方向**: 新增 `scripts/skill_e2e.py`:
- 读 SKILL.md 的 "Operations Index" 章节
- 用 `moto` mock AWS, 跑每个 op, 验证 JSON paths
- 与 SKILL.md 的 "Common JSON Paths" 块对齐
**修复成本**: ~150 行 + 5 测试。

**Gap L4.3**: **Self-Reflection Protocol (P3.4) 未与 hooks/集成** — `scripts/self_review.py`
实现完整, 但 `pre-commit hook` **不会自动调用** `record` 来记录 finding。GCL `SAFETY_FAIL`
会触发 `_reflexion.append_or_increment`, 但 hook 不触发 self_review。
**修复方向**: 在 `scripts/hooks/pre-commit` 第 2 阶段 (ruff check) 失败时调用:
```bash
python3 scripts/self_review.py record --severity P1 --title "..." --root-cause "lint failure" ...
```
**修复成本**: ~10 行 bash。

### 5.3 L4 verdict = **88%**

> 实现完整 (scripts/ 全绿, 76 KB / 70 测试), 但**强制集成** + **skill 内容 e2e** 两块
> 缺位。修复后可推到 ~95-97%。
